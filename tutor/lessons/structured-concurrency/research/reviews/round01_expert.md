**BLOCKING — Chapter 4, "His essay was called 'Go statement considered harmful'."**
What's wrong: This misquotes Smith's title. Per `research/canonical_web_agent.md` (Smith 2018b) and the script's *own* end-card in Chapter 8, the actual title is **"Notes on structured concurrency, or: Go statement considered harmful"** (2018-04-25). The script drops the primary title and subtitle marker ("Notes on structured concurrency, or:") and presents only the back half as if it were the whole name — and then contradicts itself eight minutes later by citing the full, correct title. A viewer who looks up the essay from the on-screen name in Ch. 4 alone would search for the wrong string, and anyone who knows the essay will notice the inconsistency.
Corrected wording: `His essay was called "Notes on structured concurrency, or: Go statement considered harmful."` (Screen text quoting the title should match.)

**NIT — Chapter 6, "a bare except, which catches everything" / on-screen comment "`except BaseException:  # a bare except catches this too`"**
What's wrong: The code shown is `except BaseException:`, not a literal bare `except:`. In Python 3 they're functionally identical (both catch `CancelledError`), so nothing said about behavior is false — but "bare except" is the standard term (PEP 8, pylint's `bare-except`) for `except:` with no type at all, and using it to label a typed `except BaseException:` clause is loose terminology a precise reviewer would tighten.
Corrected wording: Either show literal `except:` in the code card, or reword the narration/comment to "an except that catches everything, `BaseException` included" and drop "bare."

**NIT — data hygiene, not a script defect.** The supplied Evidence table says "task group handlers after 0.14 s" for the 1,000-concurrent-request run, but `data/runs.txt` actually reads `all 1000 handlers returned after 0.13s`. The script itself never states this number on screen (Ch. 5's counter only shows "tasks still running: 0"), so this doesn't affect the video — but the evidence doc should read 0.13 s before that number is ever put on screen in a future cut.
